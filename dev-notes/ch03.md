- **版本对齐决策(重要)**:官方 master 的 compose 默认 `milvusdb/milvus:v3.0.0`,但 Context7 上 pymilvus 文档明确覆盖的是 **2.6.x 稳定 API 面** → 按"版本对不上是返工重灾区"的规矩,**钉到 Milvus v2.6.10 服务端 + pymilvus 2.6.x 客户端**(同代配套),而非跟随 master 的 v3.0.0。
- 三个容器全部 healthy:`milvus-standalone`(v2.6.10)/ `milvus-minio` / `milvus-etcd`;`9091/healthz → OK`,`19530` gRPC 可连。

**③ 用户拒绝或纠偏**
- 无(用户主动要求装 Docker 并已完成登录跳过)。

**④ 翻车与返工**
- **凭据助手缺失**:`docker compose pull` 报 `docker-credential-desktop not found` —— Docker Desktop 的 bin 目录不在 PATH;解决:命令前 `export PATH="/c/Program Files/Docker/Docker/resources/bin:$PATH"`。
- **Docker Hub 不可达**:`registry-1.docker.io` 连接超时导致镜像无法解析;解决:在 `~/.docker/daemon.json` 增 `registry-mirrors`(`docker.m.daocloud.io`、`docker.1ms.run`)并 `docker desktop restart`,随后拉取成功。
- **WebFetch 被策略拦截**(raw.githubusercontent.com)→ 改用 jsDelivr 镜像取官方 compose,未凭记忆手写。
